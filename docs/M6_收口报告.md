# M6 收口报告：Analytics Copilot（2026-10-12）

> 本文是项目四的收口报告，只引用 **validator = v1.3** 的最终回归结果。
> 历史版本的记录（M0–M5、验证标准 v1 / v1.1 / v1.2）原样保留，不回填、不重标。
> 全文区分三类内容：**已验证事实** / **当前限制** / **后续候选**。

## 一、项目定位

面向业务分析场景的数据分析 Agent：用户用自然语言提问，系统给出
**结论 + 证据链**；证据不足、口径不匹配或超出数据能力时，明确说明而不是硬答。

一句话：**不是把中文翻译成 SQL，而是"给结论、附证据、说清口径、证不住就说不确定"。**

核心差异不是"能生成 SQL"，而是三件事：

1. **结论级证据链**：每条结论都要能落到具体查询步骤与结果行；
2. **解释强度约束**：只说到证据支持的层级，不把相关变化写成因果；
3. **能力边界可见**：数据能分析什么、不能分析什么，进入产品而不只在文档里。

## 三、版本演进与决策记录

| 版本 / 阶段 | 触发的问题 | 处理 | 为什么这么做 |
|---|---|---|---|
| `window v1.0`（P0-1） | 用户问「最近三个月」，SQL 却查全期，答案口径也没写 | 新增时间解释对象：锚点=数据集最后一天，SQL/文案/caveat 同源 | 避免自然语言解析、SQL 过滤、解释文本三处各写一套导致**口径漂移** |
| `explain v1.1`（M4） | 「为什么下降」直接拒答，体验差且边界糊 | 三级解释强度；Level 2 强制固定措辞；禁止因果结论 | 把"能不能说"变成可检查规则，而不是靠模型自觉 |
| 口径显式化（P0-2） | 系统默认按国家分析，但用户不知道被默认 | 结论前打印"分析口径"（指标 / 维度及来源 / 时间范围） | **不禁止默认，只禁止隐藏默认** |
| 兜底答案重排（P1-1） | 降级答案只有一句"我不能回答" | 先说边界 → 再给可核查事实 → 再给限制 → 最后给下一步问法 | 降级回答也必须**有用** |
| `capability v1.0`（P1-2） | 用户问"利润"时系统反问"看哪个指标" | 能力卡进入产品；能力检查前移到澄清之前 | 边界要早于澄清，否则用户以为系统理解了 |
| `validator v1.2` | 商品编码 `23084` 被当数据断言；`974.77 万` 被判无来源 | 实体编码判据（必须在结果实体列里出现）+ 单位换算归一 | 误拦**正常问法**，不再只是边界样本 |
| `validator v1.3` | 千分位 `1,070,704.67`、裸月份 `11月`、步骤引用 `步骤2` 被当断言 | 数值书写归一 | **事实不应因为排版写法改变可信等级** |

### 4.4 书写归一的效果（**反事实评估，不是跨版本比高低**）

在同一批已存输出上做反事实评估，以隔离模型波动：

| 口径 | 结论条数 | 被支持 | 支持率 |
|---|---|---|---|
| v1.2 当时的判定 | 55 | 40 | 0.7273 |
| 同批输出的反事实（书写类误判不计） | 55 | 50 | **0.9091** |
| v1.3 重跑（另一批输出，仅供参考） | 53 | 48 | 0.9057 |

**表述口径**：在相同输出样本的反事实评估中，移除书写格式误判后支持率由 0.7273 升到 0.9091，
说明主要误差来源是**验证归一化缺失**，而不是生成结果的事实错误。
**不写**"v1.3 提升了支持率"——不同版本的模型输出不同，直接比较不成立。

拦截问题构成也支持同一结论：v1.2 那次运行的 87 个问题里，千分位碎片 60、裸月份 20、
真实核对失败 7；v1.3 的 9 个问题**全部**是真实核对失败。

## 五、关键案例（失败与限制，按"能力展示"保留）

### 5.1 因果降级：宁可不答原因（保留，不修）

用户问「商品最近三个月为什么销售额下降」，系统的第一句是：

> 当前不能判断"为什么"的原因（本项目不做因果推断）。基于现有数据可以确认：…

然后给出可核查事实（按月趋势首/末/最低/最高、占比前三），再列限制，最后给可继续问的问题。
**不修的理由**：这是产品定位——系统给"数据支持的事实分析"，不是"自动找原因"。

### 5.2 时间窗：一次真正的口径漂移（已修，保留前后对照）

| | 结论首句 | 口径说明 |
|---|---|---|
| 修复前 | 从 **2010-12** 的 748957.02 到 2011-12 的 433668.01 | "以上事实为全期汇总，不按最近 N 个月过滤" |
| 修复后 | 从 **2011-10** 的 1070704.67 到 2011-12 的 433668.01 | "最近三个月，锚点 2011-12-09 → 2011-10-01 ~ 2011-12-09，末月不完整" |

关键不是"支持了最近三个月"，而是**SQL 过滤、答案口径、caveat 三者来自同一个对象**。

### 5.3 书写归一：验证的是事实，不是排版（本轮最有价值的案例）

事实是 `1070704.67`，模型写成 `1,070,704.67`。旧验证层把它读成
`1` / `070` / `704.67` 三个数字断言，于是**正确的结论被判不可信**。

这不是模型错误，是**验证层抽取错误**——LLM 的非结构化表达进入自动验证系统时的语义鸿沟。
处理方式：把"同一个数的不同写法"（千分位 / 单位 / 裸月份 / 步骤引用 / 短日期）
归一到同一读数再比对，但**不放松"必须落到证据上"**这一步。

### 5.4 holdout 误拦：语义覆盖问题，不是安全性下降

hard 集误拦率 0.4286（v1.1）→ 0.2857（v1.2/v1.3），**漏放率始终 0.0**。
剩余两条：

| 案例 | 性质 | 处置 |
|---|---|---|
| HO-HARD-03「南非贡献 2.27%」 | 中英别名表只覆盖 12 个国家 → **语义覆盖范围问题** | 延后为 v1.4 候选 |
| HO-HARD-05「23843 的退货金额约 235281.59」 | 用例给的证据行是 `AMAZONFEE`，claim 写 `23843` → **用例自身证据与结论不一致** | **保留不改**（改动冻结集等于改测试条件） |

表述口径：**漏放 = 风险；误拦 = 可优化性**。当前未发现验证安全性下降，
剩余误拦来自语义覆盖范围。

HO-HARD-05 还可以作为**测试集治理案例**：冻结集本身也是需要质量控制的对象。

### 5.5 数据边界拒答：从"莫名拒答"到"说清依据"

```
问题涉及「成本 / 利润」，超出当前数据能力：只读视图里没有成本或利润字段，算不出利润。
当前可分析：销售额 / 数量 / 退货 × 国家 / 商品 / 客户 / 时间（数据 2010-12-01 ~ 2011-12-09）
```

这条还修掉了一个顺序错误：能力检查必须**先于澄清**，否则用户问"利润"会被反问
"看销售额、销量还是退货"，反而以为系统理解了利润。

## 六、方法论结论（过程层面，比单个修复更值钱）

1. **改判定规则必须跑冻结集，不能只看手上的样例**。本轮把"数字后跟括注"当成实体引用时，
   clean holdout 立刻抓到 8 条扰动用例被放过（漏放 0 → 0.2857），规则当场回退。
2. **冻结集的 0.0 误拦率，可以和真实输出上的 0.7273 支持率同时成立**。
   holdout 由生成器按规范格式生成，测不到真实书写的多样性。
   **评测要"冻结集 + 真实输出抽样"两条腿，缺一条都会漏。**
3. **反事实评估优于跨版本比数字**：同一批输出上做 A/B，才能把规则改动的效果
   从模型波动里摘出来。
4. **收紧比放宽重要**：两处收窄（实体编码、书写归一）都同时checked了 false accept 与 false reject。

## 七、当前限制（明确保留，不在本轮修）

1. **语义覆盖范围**：维度别名表只覆盖 12 个国家；其它国家的中文表述会被判不支持；
2. **实体编码判据依赖"在结果里出现过"**：模型引用未查回的编码会判不支持（有意保守）；
3. **书写变体是枚举式覆盖**：全角标点、其它量词等新变体仍可能误拦；
4. **`description` 未清洗**：含邮费/费用/残次品行（答案里已提示，但未过滤）；
5. **会话与指标在进程内存**：重启归零（单实例形态决定）；
6. **部署是演示级**：单实例、无账号体系（仅共享访问码）、隧道 URL 非固定；
7. **任务集规模小**（18 + 4 题），且由作者构造，未经真实用户验证；
8. **上游模型不稳定**：同一问题不同轮次可能拒答/失败（如 `LLMError`），
   系统按"结构化做不到"降级，但行为会波动。
