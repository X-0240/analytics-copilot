# 面试决策卡 · M1（受控 LLM 规划）

## 决策 1：为什么让 LLM 出计划，而不是固定 workflow？

分析分支不可预先枚举：缺时间窗、缺维度、要按中间结果决定下一步查什么。
固定 workflow 会在"信息缺失"处断掉或硬猜。做法是**确定性护栏 + LLM 规划**：
LLM 只提计划，护栏决定能不能执行。

## 决策 2：为什么不把"意图"做成分类器？

意图分类会引入一个固定标签集，问题一旦超出标签就退化。
这里用**状态谓词**（指标/时间窗/维度/对比基准缺不缺）+**能力边界检查**
（预测/因果/利润直接拒答），只判断"能不能做、缺什么"，不判断"属于哪一类"。

## 决策 3：为什么只给一次修复重试？

契约要求有限重试：第一次失败把原因回灌给模型，仍不合法就**结构化失败**，
不无限重试、不静默放过。实测：一次重试把 6 例失败降到 1 例。

## 决策 4：LLM 说结论，怎么保证不编造？

结论必须**引用真实存在的步骤编号**，引用不存在的编号直接判无效；
护栏（fan-out、占比合计）发现问题时，**机械优先**把置信度压到 low，
不允许结论自称高置信。

## 决策 5：拒答算失败吗？

不算。拒答是**业务结果**：HTTP 200 + 明确原因。实测 3/3 全对
（预测、因果、无成本字段各一）。把拒答写成错误码会让上游无法区分"服务坏了"和"这事我不做"。

## 已知弱点（面试官大概率会问）

1. **T-112 计划两次撞护栏后整题报错**——正确行为应是降级为"无法完成 + 原因"，M2 修；
2. **零行结果未标注**——会让"证据链完整"看起来成立但实际无支撑，M2 修；
3. **结论正确性尚未评测**：M1 只保证"有证据链"，不保证"证据支持结论"；
4. 同一问题两次运行结论可能不同，**尚未做一致性检查**（M3）。
