# 面试决策卡 · M2（验证层 v1）

## 决策 1：为什么不接 LLM 当裁判？

项目一实测：两个模型评分者一致率只有 4/10。用一个不可靠的裁判去判另一个模型的输出，
只会把不确定性叠加。所以验证层只做**机械可判**的三件事：
数字能否追溯到结果（V1）、点名的维度值在不在结果里（V2）、
证据够不够支撑"原因"这类强结论（V3）。

## 决策 2：为什么让模型自己声明数字来源？

不声明就没法机械检查。要求结论输出 `numbers[{value, step}]` 后，
"这个数字来自哪一步"变成可核对的事实；模型一旦编造，在对应步骤里就找不到它。
这比事后从自由文本里抽数字可靠得多。

## 决策 3：V3 为什么只降级不拦？

"证据不足以支持因果"不等于"这句话错"。拦掉会把现象描述也误杀，
所以 V3 只降置信度 + 加 caveat；V1/V2 才拦——那是"数字对不上"的硬问题。

## 决策 4：验证层到底改变了什么？

**没有提高支持率**（对照表上是 −20.9pp，但两臂是两次不同运行，差异主要来自
澄清后作答的题目）。它改变的是**行为**：强结论输出 8→5，
4 个回答整体降级为"拿不到证据支持的结论"，33 条结论被拦。
诚实说法是"减少了拿不到证据支持的结论输出，并把不确定性显式暴露"，
而不是"提高了准确率"。

## 决策 5：这一层最大的坑是什么？

**验证器自己的假阳性**。首版把日期（`2010-12`）和商品编号（`23843`）当成数据断言，
把正确结论判成不可信；修掉之后同一批结论的支持率从 0.486 升到 0.857。
教训：判据本身也要被检查——**一个过严的验证器和没有验证器一样糟**。
