## 一、部署目标

1. **公网可访问的单实例 Demo**：目标读者是面试官，打开链接能提问、能看到结论 + 证据链；
2. **不以高并发为目标**：设计并发 1–2 请求/秒，单 worker、单容器；
3. **不做 SaaS 化**：无账号、无计费、无租户、无额度套餐；
4. 真正要证明的是：**可复现部署 + 可观测（日志/指标/失败统计）+ 成本可控**。

## 二、技术方案

### 2.1 容器化

- 新增 `Dockerfile`（`python:3.10-slim`）：
  装 `requirements.txt` → `COPY src/` + `data/metadata.json` → 非 root 用户运行 →
  `CMD ["uvicorn", "analytics_copilot.service:app", "--host", "0.0.0.0", "--port", "8200", "--workers", "1"]`。
- **DB 不进镜像**，挂卷到 `/app/data`（7 MB，构建机拷到目标机即可换数据）。
- 新增 `.dockerignore`：排除 `.venv/`、`data/raw/`、`eval/runs/`、`logs/`、`eval/` 大件，
  避免 45 MB csv 进构建上下文。
- `--workers 1` 是硬约束：会话在进程内存，多 worker 会把同一会话分叉；单 worker 足够 Demo。

### 2.2 服务入口

- 保留三个端点，语义不变；
- **新增 `GET /`**：单文件静态页（原生 HTML + `fetch('/ask')`），
  否则"公网 Demo"对非技术访问者只有一个 JSON 接口；
- **新增单 IP 限流**（默认 10 次/分钟）与**在飞请求上限**（默认 4），
  超出返回 429 + `code=RATE_LIMITED`，并计入指标。

### 2.3 环境变量（全部有保守默认值）

| 变量 | 默认 | 用途 |
|---|---|---|
| `AC_DB_PATH` | `/app/data/analytics.duckdb` | 只读库位置 |
| `AC_LOG_DIR` | `/app/logs` | 日志卷 |
| `AC_LLM_BASE_URL` / `AC_LLM_API_KEY` / `AC_LLM_MODEL` | 空 | 真实模型接入 |
| `AC_FORCE_STUB` | `1` | 置 `0` 才走真实模型 |
| `AC_DAILY_COST_BUDGET_CNY` | `5` | **本轮真正实现熔断**（现状未生效） |
| `AC_MAX_ROWS` / `AC_QUERY_TIMEOUT_SECONDS` / `AC_REQUEST_TIMEOUT_SECONDS` | 500 / 8 / 30 | 既有护栏 |
| `AC_RATE_LIMIT_PER_MIN` / `AC_MAX_INFLIGHT` | 10 / 4 | 新增滥用防护 |
| `AC_MAX_BODY_BYTES` | 8192 | 新增：请求体上限（按字节，不只是字段长度） |
| `AC_SESSION_MAX` / `AC_SESSION_TTL_SECONDS` | 1000 / 1800 | 新增：会话数上限与空闲回收 |

### 2.4 密钥管理

- key 只经 `--env-file .env`（本机）或平台 Secret（云）注入；
  `.env` 已在 `.gitignore`，**新增 `.env.example`**（只有键名与占位符）；
- 构建期**不传** key：镜像里没有任何凭据，`docker history` 也看不到；
- 日志、指标、响应体、`/healthz` 一律不回显 key 或 key 片段；
- key 的硬上限设在**模型账户侧**（余额即天花板），服务侧熔断只是第二道闸。

### 2.5 日志与指标

- 日志：`logs/usage.jsonl` 挂卷持久化，**按大小轮转**（约 5 MB × 3）；
  `refused` / `unable` 分支**补记成本**（现在只有 `answered` 记，会低估预算消耗）；
- **日志不留用户原文**：记 `request_id` + `question_sha256` + `question_len` + 状态 +
  成本 + 耗时，不写问题原文、不写 prompt、不写 SQL 结果全文（详见第八节）；
- 指标：`/metrics` 扩展为
  ① 既有状态计数；② `cost_cny_total` / `cost_cny_today` / `budget_remaining_cny`；
  ③ 延迟 p50 / p95；④ `rate_limited` / `inflight_rejected`。
  进程内聚合，重启归零，**可从 `usage.jsonl` 复算**（两条口径必须对得上）；
- 不引 Prometheus / Grafana：为一个 Demo 引入监控栈属于"为展示架构加组件"。

## 五、风险与对策

| 风险 | 具体表现 | 对策 |
|---|---|---|
| **API key** | 公网服务持有付费 key，泄露等于被刷钱 | 只运行时注入；镜像/git/日志三处都不落 key；账户余额即硬上限 |
| **成本** | 现状**无熔断**；单次提问实测约 0.004 元，被脚本刷 1 万次≈40 元 | 日预算熔断 + 单 IP 限流 + 在飞上限 + 每日对账（`usage.jsonl` 复算 vs 账户余额） |
| **滥用** | 无限流则任意脚本可刷 | 限流 + 请求体长度上限（已有 2–500 字）+ 拒绝并发堆积；仍被刷则下线或改共享口令（需你确认边界） |
| **数据隐私** | 数据集是公开数据集（UCI Online Retail：匿名 CustomerID，无姓名/联系方式）；**提问文本会进日志** | 页面明写"提问会被记录，请勿输入真实业务数据"；日志只留问题文本 + 状态；不接任何真实企业数据 |
| 单实例内存 | `SESSIONS` 无上限，公网长跑会涨内存 | 会话数上限 + 空闲 TTL（如 1000 个 / 30 分钟），超限按最旧淘汰 |

## 八、评审后补充的三项防护（2026-10-11 采纳）

外部评审结论：三项必补后方可执行；其余（单 worker、数据挂卷、限流、成本熔断、
metrics 扩展、日志轮转、会话 TTL、secret 注入）确认无过度设计。

### 8.1 请求输入限制（已部分存在，需补两处）

**先纠正一个事实**：`question` **已有** 2–500 字符上限（`AskRequest` 的
`Field(min_length=2, max_length=500)`），不是完全没有限制。真正缺的是：

1. `session_id` **无长度上限** → 补 `max_length=64`；
2. **请求体没有字节上限** → 字段校验发生在 JSON 解析**之后**，
   一个几 MB 的 body 会先被读进内存。补 ASGI 层中间件：按**实际收到的字节数**累计，
   超 `AC_MAX_BODY_BYTES`（默认 8192）直接 413 `code=BODY_TOO_LARGE`，
   不依赖 `Content-Length`（分块请求也能拦住）。

### 8.2 日志隐私规则（写成硬规则）

| 允许记 | 禁止记 |
|---|---|
| `request_id`、`question_sha256`、`question_len` | 问题原文 |
| 状态、错误 code、查询条数、成本、耗时 | LLM prompt / 原始响应 |
| `session_id`（随机短 id，不含身份信息） | SQL 结果全文、任何凭据 |

原因：公网访问者的输入可能含真实业务信息；最小化收集是默认口径，
不提供"记录原文"的开关（有开关就会被打开）。代价：排查线上问题时看不到当时问的是什么
——用 hash 做去重与关联，够定位"哪一类请求在烧钱"。

### 8.3 healthz 明确检查范围

现状：`/healthz` 只读 `metadata.json`，**数据库坏了也会返回 200**（假健康）。

改为三项都查：

1. API 存活（能响应即通过）；
2. **DuckDB 可读**：跑一条最小只读查询（`SELECT COUNT(*) FROM v_sales`）；
3. `metadata.json` 可加载。

任一失败 → **503** + `status=degraded` + `failed=[]` 列出失败项。
