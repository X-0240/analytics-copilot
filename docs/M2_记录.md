# M2 记录：验证层 v1（2026-10-11）

## 一、范围（按负责人冻结）

只做**验证层 v1**：V1 数值一致性、V2 证据覆盖、V3 结果充分性。
不做 LLM judge、不做规则引擎、不调模型、不扩分析类型；M1 保留为**无验证基线**。

## 二、已验证事实

| 项 | 事实 |
|---|---|
| 结论结构化 | LLM 必须输出 `claims[{text, numbers[{value, step}], dimension_values}]`：数字要写清来源步骤，维度值要来自结果 |
| V1 数值一致性 | 文本里的数字必须有声明来源，且能在来源步骤结果里找到（容差：绝对 0.01 或相对 2%） |
| V2 证据覆盖 | 结论点名的维度值必须出现在结果里（含中英别名表，只覆盖常用国家） |
| V3 结果充分性 | 归因类问题若只有单维度且无时间序列，或某步返回 0 行 → 降置信度 + 加 caveat（不删结论） |
| 行为开关 | `agent.analyze(..., verify_layer=True/False)`；服务层返回 `verification` 块；runner 支持 `--verify on/off` 与 `--compare` |
| 验证 | `pytest` **37 passed**；`ruff` 通过 |

## 三、对照数据（同一把机械尺子，2026-10-11 实测）

任务集：M1 的 18 题（12 正常 / 3 澄清 / 3 拒答）；两臂各跑一次真实模型。
**两列都由当前验证器离线复评**，避免混用运行期旧规则算出的数字。

| 指标 | 无验证层 | 有验证层 | 差 |
|---|---|---|---|
| 结论条数 | 35 | 37 | — |
| 被证据支持的结论 | 30 | 24 | — |
| 结论支持率 | 0.8571 | 0.6486 | **−0.2085** |
| 强结论输出数 | 8 | 5 | **−3** |
| 拦截数（V1/V2，当前规则） | — | 33 | — |
| 整体判 unsupported 的回答数 | — | **4** | — |
| 平均延迟 (ms) | 3526 | 3901 | +375 |
| 成本（元） | 0.049166 | 0.065476 | +0.016310 |

**这个 −20.9pp 不能归因于验证层**：两臂是两次**不同的模型运行**（同 prompt、温度 0，
但结论条数与内容仍不同，35 vs 37 条）。差异主要来自 T-201/T-202——澄清 2 轮后
带假设作答，模型给出的结论里数字无法追溯（分别被拦 9 条、15 条）。
验证层不改变结论，只判定结论；它**可归因的效果在行为层**：
强结论输出 8→5，4 个回答被整体降级为"拿不到证据支持的结论"。

要回答"验证层是否提升支持率"，必须**固定同一批结论**做前后对照，或**多次运行取分布**——
这是 M2 的方法论限制，M3 修。

## 四、最有价值的发现：验证器自身的精度问题（已修）

首版 V1 把**日期与编号**当成数据断言：

> 「2010-12 的退货量为 798 件」→ 报 `数字 2010 / 12 没有声明来源`；
> 「商品 23843 退货金额最高」→ 报 `数字 23843 没有声明来源`。

修法（仍在机械范围内）：检查前先剔除日期（`YYYY-MM`、`YYYY年M月`）、
标识（`商品/SKU/货号/编号 + 字母数字`）、排名（`前 N`、`第 N`）里的数字。

**修前修后（同一批结论、同一批证据，离线复评，0 成本）**：

| 版本 | 无验证层支持率 | 有验证层支持率 |
|---|---|---|
| 首版（含假阳性） | 0.4857 | 0.4750 |
| 修精度后 | **0.8571** | 0.6486 |

即：**不修这个假阳性，这一层会把大量正确结论判成不可信，直接毁掉可信度**。

## 五、失败案例与限制

1. **3 例 error**（T-101 / T-107 / T-112）：计划两次都撞护栏后仍报错，
   而不是降级为"无法完成 + 原因"——M1 遗留项，M2 未修（列入 M3）。
2. **V3 从未触发**（降级数 0）：本次任务集里"归因类且单维度"的组合没出现，
   不是它没实现，而是**没覆盖到该情形的用例**——需要补边界用例。
3. **误拦截率与漏放率仍缺**：需要独立判定者；按纪律不做 LLM judge，
   因此只能报"拦截数"，不能报"误拦率"。这是有意的口径留白，不是遗漏。
4. 维度值匹配依赖**中英别名表**（只覆盖 12 个常用国家），未覆盖的值会被误判为 V2 失败。
5. 结论支持率是**机械口径**：判的是"数字能否追溯到结果 + 维度值是否在结果里"，
   **不等于"分析结论在业务上正确"**。

## 六、下一步（M3）

1. 固定同一批结论做前后对照（或多次运行取分布），把支持率差异与噪声分开；
2. 修"两次修不好 → 降级"（不再报 error）；
3. 补 V3 能触发的边界用例；
4. 补 holdout 与阈值冻结流程。
