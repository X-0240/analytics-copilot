# M3 记录：可靠性修复 + 标准冻结 + 两个分离实验（2026-10-11）

## 一、范围（按负责人冻结）

## 二、M3-A：已完成事实

1. **两次修不好 → 结构化失败**：新增 `UnableToComplete`，规划或结论两次不合法时
   不再抛异常，而是返回 `status=unable_to_complete` + 原因（服务层 HTTP 200，
   计入 `unable` 计数，不混进 `errors`）。
2. **补 V3 边界任务**：`eval/tasks/m3_boundary_tasks.json`（4 题，含"为什么英国销售下降"
   "哪个商品导致下降""客户维度谁导致下降""按国家+商品两维度看"）。

## 三、M3-B：验证标准冻结

## 四、M3-C 实验 1：验证能力（固定结论集，0 成本）

结论、来源步骤、期望判定全部由作者构造（12 例 / 13 条 claim），把验证器当被测对象：

| 指标 | 值 |
|---|---|
| 期望"不支持"的结论数 | 5 |
| 实际抓出 | **5**（漏放率 **0.0**） |
| 误拦率（冤枉正确结论） | **0.0** |
| 结论支持率 | **1.0** |
| V3 判定正确 | **2/2** |

**口径限制**：期望判定是作者自己标的，1.0 只说明"验证器与作者标注一致"，
**不等于**验证器在未知数据上准确——那需要 holdout。

修正过程中发现并修掉两个假阳性（M2 遗留的同类问题）：
① 退货金额写绝对值（数据里为负）被误判 → 数值匹配放宽为"绝对值相等"（有意取舍）；
② 裸字母数字标识（`85123A`）被当成数字 → 剔除含字母且长度 ≥4 的 token。

## 五、M3-C 实验 2：产品行为（18 题真实模型，同一把尺子离线复评）

| 指标 | 无验证层 | 有验证层 | 差 |
|---|---|---|---|
| 结论条数 / 被支持 | 38 / 29 | 39 / 29 | — |
| 结论支持率 | 0.7632 | 0.7436 | **−0.0196** |
| 强结论输出数 | 8 | 6 | **−2** |
| 拦截数（V1/V2） | — | 27 | — |
| 整体判 unsupported 的回答 | — | **4** | — |
| 平均延迟 / 成本 | 3727 ms / 0.068026 元 | 3236 ms / 0.061544 元 | −491 ms / −0.0065 元 |

**结论口径**：支持率基本持平（−2.0pp，两臂仍是**两次不同运行**，差值在噪声范围内），
可归因的是**行为变化**：强结论输出减少、4 个回答被整体降级、27 条结论被拦。
延迟与成本的差异是模型调用波动，验证器本身是纯机械计算、成本为 0。

## 六、M3-A2 边界任务结果（真实链路，4 题）

| 任务 | 结果 | 说明 |
|---|---|---|
| T-401「为什么英国销售下降」 | **refused** | 模型判定为因果推断，超出能力边界；与"澄清 vs 拒答"重叠的已知现象一致 |
| T-402「哪个商品导致下降」 | answered（5 条全支持，无降级） | 计划里包含了趋势，V3 未触发 |
| T-403「客户维度谁导致下降」 | answered（5 条全支持，**V3 降级 1 次**） | 真实链路里 V3 首次触发，置信度降到 low，状态 `partially_supported` |
| T-404「按国家+商品两维度看」 | answered（5 条全支持，无降级） | 两维度 → V3 不触发，符合规则 |

## 七、限制（如实记录）

1. 两个实验的**样本都小**（固定集 12 例、行为实验 18 题），只作方向性证据；
2. 支持率仍是**机械口径**，不等于业务正确；
3. 误拦率只在**作者构造的固定集**上测得 0.0，未知数据上未验证；
4. 归因类问题与"因果推断"边界仍有重叠（T-401 被拒答而非降级），
   属产品口径问题而非实现缺陷，需要时在 M4 明确"归因 ≠ 因果推理"的判据；
5. 纯数字编号（如 `23843`）不带前缀时仍会被当成数字断言（已知限制）。

## 八、下一步（M4 候选）

2. 把"归因 vs 因果"的判据写成可检查的规则（当前靠模型自行判断）；
3. 部署（容器化 + 公网 + 日志 + 指标端点）作为 M5，尚未开始。
