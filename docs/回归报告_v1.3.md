# 全量回归报告（v1.3，2026-10-12）

## 一、结论

1. **回归本身又发现了一个问题，因此多升了一个版本**：模型输出的**书写形式**
   （千分位 `1,070,704.67`、裸月份 `11月`、步骤引用 `步骤2`、描述里的短日期 `21/5/10`）
   被机械扫描当成数据断言。这是**同一个数的不同写法**，与 v1.2 的单位换算属同一族，
   于是升 **v1.3：数值书写归一**（规则见 `docs/验证标准_v1.3.md`）。
2. 归一之后，主集结论支持率从 0.7273（v1.2 那一次运行）升到 **0.9057**；
   用**同一批输出**做的反事实复评是 0.9091——**差值几乎全部来自规则，而不是模型波动**。
3. 两组 holdout 的漏放率仍为 **0.0**、误拦率未上升（hard 集 0.2857，与 v1.2 相同）。
4. 一个更重要的发现见第五节：**holdout 上的 0/0 与真实输出的 0.7273 可以并存**。

## 三、v1.3 改了什么（书写归一）

| 写法 | 例子 | 处理 |
|---|---|---|
| 千分位 | `1,070,704.67` | 归一成一个数字，不再拆成 `1` / `070` / `704.67` 三个碎片 |
| 裸月份 / 日 | `11月为 1461756.25` | 当作时间指代，不做数据断言 |
| 步骤引用 | `步骤2 中销售额最高…` | 跳过（结论**被要求**引用步骤编号，不能反过来判它没来源） |
| 描述里的短日期 | `reverse 21/5/10 adjustment` | 当作日期串跳过 |

为什么要做：模型写千分位很常见，而验证层不认，导致**正确结论被判不可信**。
这与 v1.2 的单位换算是同一族问题（同一个数，不同写法），所以按升版处理，
v1.2 文档原样保留。

## 五、这轮最重要的发现（流程层面）

**冻结集上的 0.0 误拦率，与真实输出上的 0.7273 支持率，可以同时成立。**

原因是 holdout 是用**生成器按规范格式**造的：数字不带千分位、日期只有 `YYYY-MM` 形式、
描述里没有斜杠日期。于是冻结集测的是"规则覆盖是否完整"，测不到"真实书写的多样性"。

这条正好印证了负责人此前的判断——**修规则必须同时看 false accept 和真实输出**：

| 检查 | 这次的结果 |
|---|---|
| 冻结集漏放（false accept） | 收紧括注规则时被抓到 0 → 0.2857，已回退 |
| 真实输出支持率 | 抓出书写归一缺失（0.7273 → 0.9057） |
| 两者都没做的后果 | 会写出"误拦降到 0.2857、系统很稳"的漂亮结论，而 Demo 实际在误判 |

**建议写进 M6**：验证层评测要"冻结集 + 真实输出抽样"两条腿，缺一条都会漏。

   尚未覆盖——新增写法时仍可能误拦。
