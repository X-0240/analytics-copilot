## 一、为什么要两组 holdout

M3 的固定集是"我自己写题干、自己标期望"，存在自出题自评分的风险。
所以 M4 换成**标签由生成规则决定**的两组集：

| 组 | 怎么造 | 标签来源 | 用途 |
|---|---|---|---|
| `holdout_v1.json`（58 例） | 从真实库取结果行，按规则合成各类违规与合法结论 | **生成规则**，非人工判断 | 规则覆盖：每种违规类型是否抓得住 |
| `holdout_hard_v1.json`（8 例） | 专门去撞规则边界（容差附近、别名表外、单位换算、裸编号） | **业务意图**（这句话业务上是否被支持） | 未知样本上的误拦与漏放 |

生成器：`eval/holdout/gen_holdout.py`（seed 20261011，可复现）。

|---|---|
| `holdout_v1.json` | `28218D34961D084BDC8CD5A3F05CED2B843ED53A308F26DE7427D2AEF3A04A7E` |
| `holdout_hard_v1.json` | `6A535C1A335CF7EB5756EEF7BEB61981D585F1175A853D0ECD8CF044F8860B93` |

## 二、结果（冻结规则 v1，未做任何调整）

### holdout_v1（规则覆盖，58 例 / 58 条结论）

| 指标 | 值 |
|---|---|
| 期望"不支持" | 28 |
| 抓出 | **28（漏放率 0.0）** |
| **误拦率** | **0.0** |
| V3 判定 | 2/2 |

### holdout_hard_v1（边界难度，8 例 / 8 条结论）

| 指标 | 值 |
|---|---|
| 期望"不支持" | 1 |
| 抓出 | **1（漏放率 0.0）** |
| **误拦率** | **0.4286（7 条业务支持的结论里拦掉 3 条）** |
| V3 判定 | 1/1 |

**三条误拦全部命中已知限制，逐条可归因**：

| 案例 | 情形 | 归因 |
|---|---|---|
| HO-HARD-03 | 「南非贡献 X%」 | 中英别名表只覆盖 12 个常用国家，表外国家判不出对应关系 |
| HO-HARD-04 | 「约 974.77 万元」 | 机械匹配不做**单位换算**（万/千） |
| HO-HARD-05 | 「23843 的退货金额约 …」 | 纯数字编号无前缀时与数字断言无法区分 |

**结论口径**：在未知样本上，**漏放为 0，误拦率 42.9%，且误拦全部有明确归因**。
换句话说，当前验证层的风险不是"放过错误结论"，而是"冤枉一部分正确结论"；
对用户信任而言后者同样要命，因此这三条登记为**下一版规则的改进候选**。

## 三、本轮守住的纪律

1. **看到误拦 42.9% 之后没有去改规则**——按冻结纪律，改规则须升版本，
   且不得用它回填 M3/M4-A 的历史结果；
2. 两组 holdout 的标签来源都写清楚：一组来自生成规则，一组来自业务意图判断；
3. 没有把 58 例的 0.0/0.0 写成"验证器准确率 100%"——
   它只说明**对"干净的违规实例"规则覆盖完整**。

## 四、下一步（M4-B / M4-C）

1. **M4-B 解释强度判据**（Level 0 事实 / 1 相关因素 / 2 可能解释 / 3 因果结论）：
   把"为什么…"从直接拒答改成"给到证据允许的层级 + 明确不能给因果结论"，
   并在验证层加一条越界检查（结论用因果措辞但证据只到 Level 1/2 → 降级）；
   **升版本 v1.1**，不动 v1 记录。
2. **M4-C 重跑产品行为实验**：对比解释强度加入前后的拒答数、caveat 数、强因果声明数。
3. 三条误拦限制（别名表 / 单位换算 / 裸编号）留到 **v1.2** 处理，本轮不修。
