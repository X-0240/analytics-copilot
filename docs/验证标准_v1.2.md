# 验证标准 v1.2（2026-10-12 升版）

> **v1.2 取代 v1.1**。v1 与 v1.1 原文与它们的结果原样保留，不受本轮影响。
> 本轮只改两处**判定边界**，不改支持规则的主干（V1 数值一致性 / V2 证据覆盖 /
> V3 充分性 / V4 解释强度）。
> 纪律：v1.1 的历史结果不回填；**v1.1 与 v1.2 的数字不得混用**，
> 引用哪一版必须写清（`eval/runs/` 里的 run 目录名带版本）。

## 一、为什么升版

两条误拦已经**影响正常问法**，不再只是 holdout 上的边界样本：

| 现象 | 例子 | 影响 |
|---|---|---|
| 纯数字商品编码被当成"没来源的数字断言" | `23084（RABBIT NIGHT LIGHT）…` | 商品类问题被判不可信 |
| 单位换算写法被判"数字没有声明来源" | 证据 `9747747.93`，结论写「约 974.77 万」 | 常见金额表述被判不可信 |

## 二、改动一：实体编码不算数值断言（收窄规则）

**判据只有一条**：这个裸数字**真的出现在结果的实体字段列里**
（`stock_code` / `customer_id` / `invoice_no` / `dimension_value`）。

- ✅ `商品 23084（RABBIT NIGHT LIGHT）销售额为 56289.81`：23084 在结果的编码列里 → 跳过；
  56289.81 仍要声明来源并核对；
- ❌ `编码 99999 的销售额为 56289.81`：结果里没有 99999 → 仍判"没有声明来源"；
- ❌ `商品 23084 比 22086 高 20%`：编码跳过，但 **20% 仍必须可核对**。

**试过更宽的写法，被 holdout 挡回来了**：曾经把"数字后面跟括注"也当成实体引用，
结果 clean holdout 上把 8 条「扰动数字 +（声明来源为真实值）」的用例全部放过，
漏放率从 0 升到 0.2857。已回退到"必须在结果里出现"这一条。
**这一次收紧比放宽重要**——记录在案。

## 三、改动二：单位换算只认确定换算

结论文本里带单位（`千` / `万` / `十万` / `百万` / `千万` / `亿`）时，
把**文本**和**声明值**都按同一个系数归一后再比对，两头都要落到证据上：

1. 文本 `974.77 万` → 读法 `{974.77, 9747700}`；
2. 声明可以写原始值 `9747747.93`，也可以写 `974.77`；
3. 换算后必须能在该步骤结果里找到（容差沿用 v1：绝对 0.01 / 相对 2% / 绝对值相等）。

保住的边界：

- ❌ 无来源的「约 100 万」→ 两种读法都找不到证据 → 仍判不支持；
- ❌ 单位写错（「974.77 千」）→ 换算不上 → 仍判不支持。

## 六、口径与限制

1. `scripts/holdout_eval.py` 是**可复现评测脚本**（M4-A 当时用临时脚本跑、删掉后无法复现，
   本轮补上）：它按生成器的约定还原列名（首格是字符串且非数字 → 视作维度值列），
   否则 v1.2 的实体编码规则在 holdout 上无法生效；
2. 归一化只覆盖**确定单位**（千/万/十万/百万/千万/亿）；"约""左右"这类模糊词不参与换算；
3. 实体编码判据依赖"结果里出现过"，所以**模型引用一个没有被查回来的编码时会判不支持**
   （与 HO-HARD-05 同源）——这是有意的保守取向；
4. 别名表扩充、以及"多行结果里的非首列实体"仍未覆盖，登记为下一轮候选。
