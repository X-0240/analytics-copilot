# 验证标准 v1.1（2026-10-11 升版）

> **v1.1 取代 v1**。v1 原文与它的全部结果原样保留（`docs/验证标准_v1.md`，
> SHA-256 `FCEA9677…`，在本轮内未改动一个字符）。
> 升版原因：新增**解释强度模型**、把**因果类提问**从"直接拒答"改成"给到证据允许的
> 层级 + 固定边界措辞"、并补齐**模型输出/执行失败的降级口径**。
> 纪律：v1 的历史结果**不回填、不重标**——它们对 v1 规则依然成立，因此本轮**没有**
> 标 `INVALIDATED`；`INVALIDATED` 机制保留给"同一版规则被修正、旧结果作废"的场景。
> **v1 与 v1.1 的数字不得混用或混着汇总**，报告里引用哪一版必须写清。

## 一、解释强度模型（v1.1 新增，负责人冻结）

| 等级 | 定义 | 允许的证据 |
|---|---|---|
| **Level 1 事实描述** | 单指标 / 单维度 | 有直接查询证据即可 |
| **Level 2 相关性解释** | 至少 1 个可比较维度 **且** 有时间变化或对照证据 | 输出**必须**包含固定措辞「该结果展示相关变化模式，不能证明因果关系」 |
| **Level 3 因果结论** | — | **本项目禁止输出**；用户提因果假设时只做数据一致性验证，不得声明因果成立 |

### 等级怎么算（机械，不靠模型自述）

`src/analytics_copilot/explain.py::evidence_level`：

1. 任一执行步骤返回 0 行 → Level 1；
2. 计划里出现可比较维度（`country` / `stock_code` / `customer_id`），
   且（有 `date_trunc` 时间序列 **或** ≥2 个维度）→ Level 2；
3. 其余 → Level 1；**永远不返回 Level 3**。

### 越界检查 V4（结论不得说到证据支持不到的地方）

因果词表（机械可判）：`导致` `造成` `引起了` `引起` `因为` `由于` `根本原因`
`证明了` `源于`。

claim 文本命中词表 → 记一条 V4 → **整题置信度降为 low + 追加边界措辞**
（Level 2 附「该结果展示相关变化模式，不能证明因果关系」，
一律附「本项目不支持因果结论：只能做数据一致性验证，不能声明因果成立」）。
**不重写结论文本**——只降级 + 显式说明，保留原始输出可追溯。

### 因果类提问的处理（v1.0 → v1.1 的行为变化）

- v1.0：提问或计划命中"因果"→ 整体拒答。
- v1.1：提问（`因果|原因|为什么|导致|因为`）或模型给出的拒答理由命中因果词
  → **不再拒答**，改走确定性兜底计划（`_causal_fallback`），
  结论写成"本次只做事实与相关变化描述：最大维度是 X（值 Y）"，
  置信度固定 low，并附上固定边界措辞。
- 仍然拒答的只剩两类：**预测**（含"预计"）、**需要成本字段的利润/毛利类**。

边界措辞**对所有出口生效**：LLM 路径由验证层 V4 追加，无 key 的规则路径
同样按算出的等级追加（否则 Level 2 会缺那句必须有的声明）。

## 二、v1 未变的部分

支持规则（V1 数字来源 / V2 维度可核对）、数值与维度匹配阈值、别名表、
步数上限与 SQL 护栏、V3 结果充分性、澄清轮数（2 轮）**均沿用 v1**，详见
`docs/验证标准_v1.md` 第一至三节，此处不重抄，避免出现两份互相冲突的口径。

## 三、降级口径补全（v1.1）

统一原则：**凡是"模型或数据造成的做不到"，都返回结构化 `unable_to_complete`
+ 原因；只有环境故障才记 `errors`。**

| 情形 | 行为 | 状态值 |
|---|---|---|
| 计划两次都过不了护栏 | 结构化"做不到 + 原因" | `unable_to_complete` |
| **SQL 执行期被拒**（列不存在 / 类型不匹配等，v1.1 新增） | 同上 | `unable_to_complete` |
| **结论 JSON 解析失败**（v1.1 新增） | 同上 | `unable_to_complete` |
| LLM 传输失败（HTTP / 网络，`LLMError`） | 不降级，按环境故障记 | `error` |
| 问题超出能力边界（预测 / 利润类） | 明确拒答并给原因 | `refused` |
| 缺必要信息（指标 / 比较维度） | 先澄清，最多 2 轮 | `need_clarification` |

## 五、限制（如实记录）

1. **两臂不同运行**：因果类拒答 **2 → 0**（主集 T-302 + 边界 T-401）是**规则改动**
   直接决定的（policy 变化），
   其余差值在运行噪声范围内，不能当效果提升；
2. **V4 只在这些题上触发 1 次**：说明模型很少主动写因果措辞，
   该检查目前是"廉价保险"，覆盖面受任务集规模限制（22 题）；
3. **兜底路径不过 V1/V2**：`_causal_fallback` 的结论由查询结果机械拼出
   （不经过模型），因此没有 claim 级复核；
4. 词表判定是**机械匹配**：同义改写（如"拖累了""与…同步回落"）会漏检；
5. holdout 上的三条误拦（别名表外国家 / 单位换算 / 裸数字编号）**本轮不修**，
   留给 v1.2 的验证器精度任务。

## 六、v1.2 待办（已登记，不做）
